# rpc-demo Architecture Notes

## 模块目标

这个模块适合学习 RPC 框架的核心骨架：

- 服务暴露
- 服务发现
- 本地代理
- 网络通信
- 序列化与反序列化
- 请求响应模型
- 容错与超时

这是理解 Dubbo、gRPC 甚至很多自研框架的关键入口。

## 值得先思考的问题

- 为什么“远程调用”要伪装得像“本地调用”？
- 如果一个方法调用跨了网络，它和本地方法调用最本质的差别是什么？
- 为什么 RPC 框架通常会同时关注代理、协议、序列化、连接管理和服务发现？
- 一个简单的 HTTP 请求，为什么不等于一个完整的 RPC 框架？

## 核心设计思想

### 1. 屏蔽分布式调用复杂度

RPC 的第一层目标，是让业务开发者用“像本地方法一样”的方式发起远程调用；但框架内部必须真实面对网络失败、超时、半连接、重试和序列化兼容等问题。

### 2. 调用抽象必须分层

一个相对完整的 RPC 框架，通常要拆开看：

- 代理层：业务方如何发起调用
- 注册发现层：如何找到服务
- 协议层：请求如何编码
- 传输层：数据如何发送
- 编解码层：对象如何变成字节流
- 容错层：失败时怎么办

### 3. 先跑通链路，再讨论性能

学习 RPC 时很容易一开始就盯着 Netty、高性能、连接池，但更重要的是先把一条完整调用链想清楚：

- 调用方如何感知服务接口
- 请求如何被唯一标识
- 服务端如何定位具体方法
- 响应如何回到正确的调用方

## 和 Netty 的关系

这个模块后续非常适合和 Netty 联动学习：

- RPC 不是等于 Netty
- 但很多 RPC 框架用 Netty 作为高性能通信底座
- 所以 Netty 更像“传输引擎”，RPC 更像“调用抽象 + 治理能力”
